# 🌍 Internationalization

Structure for many locales from day one, even if you launch with one. Retrofitting i18n later means touching every string in the app.

## A tiny, dependency-free translator
You rarely need a heavy i18n library. A flat key catalog + interpolation covers most apps:
```ts
export function createTranslator(catalog: Record<string, string>) {
  const t = (key: string, vars?: Record<string, string | number>) => {
    const tmpl = catalog[key];
    if (tmpl === undefined) return `⟦${key}⟧`;   // loud miss — never a silent fallback
    return vars ? interpolate(tmpl, vars) : tmpl;
  };
  t.has = (key: string) => Object.hasOwn(catalog, key);
  return t;
}
```
- **Missing keys render loudly** (`⟦some.key⟧`) so gaps are obvious in dev, not invisible in prod.
- Put it in a shared `packages/i18n` so web and mobile share the same catalog and locale rules.

## Catalog: nested authoring, flat lookup
Author by feature namespace, flatten to dot-keys at build/load:
```json
{
  "nav": { "home": "Home", "billing": "Billing" },
  "approvals": {
    "empty": "Nothing waiting on you.",
    "pending": "{count} pending approval",
    "pending_plural": "{count} pending approvals"
  }
}
```
→ `nav.home`, `approvals.pending`, `approvals.pending_plural`. Interpolate with `{var}` placeholders; pick the `_plural` key by count.

## Locale resolution
- Supported set + a default: `["en","es","pt","fr","de"]`, default `en`.
- **Normalize tags:** strip region (`pt-BR` → `pt`), lowercase, fall back to default.
```ts
export function normalizeLocale(tag?: string, supported = SUPPORTED, def = "en") {
  if (!tag) return def;
  const primary = tag.split("-")[0].toLowerCase();
  return supported.includes(primary) ? primary : def;
}
```
- **Mobile** passes locale per request (`?locale=es`); the same normalization runs client-side ([mobile](../stack/mobile.md)).

## SRP for i18n
i18n is itself a set of single-responsibility modules — don't cram it into one file ([SOLID/SRP](../architecture/solid-srp.md)):
```
packages/i18n/src/
├── translator.ts   # createTranslator() — lookup + interpolation only
├── catalog.ts      # nested → flat catalog flattening
├── locales.ts      # supported set, default, normalizeLocale()
├── interpolate.ts  # {var} substitution + pluralization
└── index.ts        # public exports
```
- **The translator doesn't know about locale resolution; the resolver doesn't know about interpolation.** One reason to change each.
- Catalog files (`en.json`, `es.json`, …) are data, not code — keep them out of the logic modules.
- This is what lets web and mobile share `translator`/`locales` while supplying their own catalogs.

## 🚦 Catalog parity gate (in `bin/check`)
`⟦key⟧` catches gaps in dev; the gate makes sure none reach prod. Source locale `en` is the truth; every other catalog must match it exactly.

| Check | Fails when |
|---|---|
| Missing key | key in `en` absent from any locale (or extra key not in `en`) |
| Placeholder mismatch | `{var}` set differs from `en` for the same key |
| Unused key | key in `en` never referenced by a `t("…")` call |
| Dynamic key | `` t(`…${x}`) `` — keys must be string literals so the gate can see them |

```ts
// scripts/i18n-check.ts — `bun scripts/i18n-check.ts` from bin/check. Exit 1 on any finding.
import { Glob } from "bun";
import { flatten } from "../packages/i18n/src/catalog";
import { SUPPORTED } from "../packages/i18n/src/locales";

const load = async (l: string) => flatten(await Bun.file(`packages/i18n/locales/${l}.json`).json());
const vars = (s: string) => [...s.matchAll(/\{(\w+)\}/g)].map((m) => m[1]).sort().join(",");
const errs: string[] = [];
const en = await load("en");

for (const l of SUPPORTED.filter((x) => x !== "en")) {
  const cat = await load(l);
  for (const k of Object.keys(en)) {
    if (!(k in cat)) errs.push(`${l}: missing ${k}`);
    else if (vars(cat[k]) !== vars(en[k])) errs.push(`${l}: placeholders differ in ${k}`);
  }
  for (const k of Object.keys(cat)) if (!(k in en)) errs.push(`${l}: extra key ${k}`);
}

const used = new Set<string>();
for await (const f of new Glob("{apps,packages}/**/src/**/*.{ts,tsx}").scan()) {
  const src = await Bun.file(f).text();
  for (const m of src.matchAll(/\bt\(\s*["'`]([\w.]+)["'`]/g)) used.add(m[1]);
  if (/\bt\(\s*`[^`]*\$\{/.test(src)) errs.push(`${f}: dynamic i18n key`);
}
for (const k of Object.keys(en))
  if (!used.has(k) && !used.has(k.replace(/_plural$/, ""))) errs.push(`en: unused ${k}`);

if (errs.length) { console.error(errs.join("\n")); process.exit(1); }
```
- Output is the translation worklist: one line per gap, locale-prefixed.
- Native apps reading the same catalogs → add their call-site pattern (`L("…")` / `stringResource`) to the scan.
- Locale with more than two plural forms (pl, ru, ar) → switch `_plural` to `Intl.PluralRules` categories (`_one`, `_few`, `_many`, `_other`) and have the gate require every category that locale's rules return.

## 🤖 Agents translating
The gate says *what* is missing; the agent fills it with UI context, never word by word.

1. **Worklist** = gate output. Batch by namespace (`approvals.*`) so terms stay consistent within a feature.
2. **Read the caller** for each key: button, heading, error, `aria-label`, fragment? Length budget? What fills each `{var}` at runtime?
3. **Follow `packages/i18n/glossary.md`**: per-locale term table, do-not-translate list (product name, plan names), register (`tú`/`usted`, `du`/`Sie`), audience.
4. **Preserve** placeholders byte-for-byte, plural keys, markup. Reorder placeholders when grammar needs it — named `{var}` exists for that ([ux-copy.md](ux-copy.md#-i18n-safe-copy)).
5. **Run the gate**, then screenshot the longest locale (often `de`, commonly ~30% longer than `en`) at mobile width → [design-review-loop.md](design-review-loop.md).
6. **PR body lists** keys changed per locale, glossary terms added, and strings flagged for native-speaker review: legal, pricing, marketing headlines.

Context beats dictionary: `nav.home` in Turkish is `Ana Sayfa` (home page), not `Ev` (a house). Ambiguous source string → add a per-key note to `glossary.md` once resolved, not a silent guess.

## Rules
- **No hardcoded user-facing strings** — every one goes through `t()`.
- **Catalog parity gate runs in `bin/check`** — missing key, placeholder mismatch, unused or dynamic key fails the build.
- **One catalog per locale**, namespaced by feature; keep keys stable.
- **Dates, numbers, money are NOT i18n strings** — format them with `Intl` per locale → [dates-money-timezones.md](dates-money-timezones.md).
- Keep the shared locale set identical across web + mobile so translations are written once.
- **SRP:** translator / catalog / locale-resolution / interpolation are separate modules.
